# 224. One frame in two places: listed from the copy that is there (2026-10-02)

§216 made a frame and its archive copy one frame in All roots: the
archive's row left out where its content key is also under a local
root, on the rows the read brings, nothing asked of the disk (§217).
The 0.4.0 sentence asks more: the frame opened from the copy that is
online, so that "back up, then delete local" removes nothing from the
library.

**What a scratch library showed.** A shoot backed up and its raws
deleted by hand left the shoot's folder empty; an emptied folder is an
unmounted drive's mount point to the index (§160), so the local rows
stood, hid the archive's copies, and the editor opened a file that was
not there. With the folder itself deleted, or the root unplugged, the
same: the hide was decided before the read looked at any folder, and an
offline root's rows are kept on purpose, to be shown dimmed (§160), so
the frame was a dimmed stand-in with a picture on the archive behind
it.

**Now.** A local row hides the archive's copy only while it is there:
its root answering and its folder readable. The read looks at the local
rows first, as it did, one `read_dir` a folder; the archive's twins of
the local frames found there are left out without a look at their
folders, so the disk cost of §217 stands; the rest of the archive's rows
are looked at as any folder is. A frame whose local copy's folder is
gone, or whose root is offline, is listed from the archive, with its
picture, and the dimmed stand-in for the local copy goes, so the frame
is not shown twice. Turning the mark off still brings every row back.

**What is left, on the roadmap.** The emptied-but-present folder is
still §160's ambiguity: a drive unmounted and a shoot deleted by hand
look alike without a stat per file, which the read avoids by design;
the editor's own delete forgets its rows outright (§218), so the
editor's path is right already. The sidecar written to both copies when
both are there belongs with the reconciliation design, which decides
what two copies that diverged do. And the frame on screen when its root
goes stays as it was (§160); following it to the archive's copy is a
change of path under an open edit and waits for that same design.
