# §458. The switch keeps the frame on screen

*2026-10-30.* Flipping With subfolders in the Loupe made the
navigator's picture blink (issue 57). The switch opened the folder
again as a new view, and an open replaces the whole list: the frame on
screen was selected again as a new frame, decoded and developed over,
the navigator blank until the develop landed. The list changing under
a frame already has its path, the merge a sort or a watched folder
uses, which keeps each file's sidecar, picture, row, and place in the
selection and leaves the frame on screen alone. The switch now takes
that path when the frame on screen is in the list it brings: always
when it turns on, and when it turns off only for a frame directly in
the folder. What the window draws from the view rather than the list,
the tree's mark, the tiles, the folder named, and the Sort menu,
follows at once. A frame of a folder below with the switch turned off
is not in the new list, and that case opens the view as before, since
the merge would keep a frame that is not in the list it brings. A
folder opened from the disk under another spelling of its path is
taken the same way, opened again, rather than matched by path.
